# Decisions

One line each: date, decision, why.

- 2026-11-06 — Python packages live at the repo root (`contracts/`, `shared/`, `compiler/`, `enforce/`) in one uv project — simplest imports for a hackathon; split later if needed.
- 2026-11-06 — Bumped SCHEMA_VERSION to 0.2.0 for Expense/Ruleset/Trace models; enforce engine filters rule applicability by category/budget line before evaluation — prevents cross-category budget pollution while maintaining pure deterministic <10ms execution.
- 2026-11-06 — Built compiler citation verification and FastAPI bridge (port 8000) with Live Compliance Studio in web UI — connects PDF uploads and live spend evaluation to Next.js with local offline fallback.
- 2026-11-07 — Citations require char_start/char_end matching len(quote); SCHEMA_VERSION 0.3.0 — CLAUDE.md requires every rule to carry verified offsets.
- 2026-11-07 — Rule params (dates, dollar thresholds, categories) are parsed from the cited clause; unparseable candidates are rejected, never defaulted — the old proposer hard-coded 2026 dates for any grant.
- 2026-11-07 — Sample ruleset is compiled from fixture page text by the real compiler — fixture citations are verified by construction.
- 2026-11-07 — Web studio has no client-side evaluator fallback; if the API is down it says so — a second, divergent evaluator in the UI (with a hard-coded latency) could show verdicts the engine never made.
- 2026-11-07 — threshold_approval triggers at >= threshold — clauses read "$X or more".
- 2026-11-07 — The LLM only returns (rule_type, page, verbatim quote); all params are parsed from the quote by derive_params — keeps "LLMs never do arithmetic" and makes every rule checkable.
- 2026-11-07 — No temperature setting: current Claude models reject sampling params; reproducibility comes from the prompt-hash response cache instead (deviation from CLAUDE.md's "temperature 0").
- 2026-11-07 — Default model claude-opus-5-5 at effort "medium", overridable via FINEPRINT_LLM_MODEL; server-side fallback ("default") enabled so a refusal re-runs on Anthropic's recommended model.
- 2026-11-07 — LLM is used for uploads only when ANTHROPIC_API_KEY is set (FINEPRINT_PROPOSER=keyword forces offline); on LLM failure the compile falls back to the keyword proposer and reports it. Fixtures and tests always use the keyword proposer.
- 2026-11-07 — Root conftest strips ANTHROPIC_API_KEY and redirects the LLM cache for every test; a repo scan test fails on anything shaped like an Anthropic key.
- 2026-11-07 — Rules have status proposed/approved; only approved rules are enforced, and grant compiles produce proposed rules — nothing AI-extracted blocks a payment before a person approves it (studio auto-approves until the review screen exists).
- 2026-11-07 — Company policy rules are drafted from the user's own text; the user's sentence is the citation, amounts are parsed by code, enum fields are validated, and anything unclear becomes a multiple-choice question whose answer is recorded on the rule.
- 2026-11-07 — Several rulesets (grant + company policy) are evaluated together; the strictest outcome wins and each trace records its source. Every FAIL/ESCALATE carries a deterministic "fix" hint.
- 2026-11-07 — Rule-card examples run the real engine on synthetic expenses, so examples can never disagree with enforcement.
- 2026-11-07 — Coverage report classifies every clause (rule / flagged / rejected / no rule); the LLM can flag ambiguous clauses, which are verified like rules but never enforced.
- 2026-11-07 — Rulebook store is in-memory for now (api/main.py RULESETS/DRAFTS); persistence stays with b/persistence.
- 2026-11-07 — Offline policy reader (compiler/policy_offline.py) handles common phrasings without an API key; its output goes through the same validation as Claude's. Used when no key is set/enabled or Claude fails, and labelled "offline" in the draft.
- 2026-11-07 — Bare-bones test page served by the API at /playground (make playground) so the policy -> questions -> approve -> enforce flow can be tried without the web app or a key.
- 2026-11-07 — Policy setup is a chat: the company uploads its existing policy (PDF/text, multi-page), it's read into rules, and the assistant then resolves gaps one at a time (missing details, exceptions, vague wording, unsupported limits, missing topics, grant conflicts). Answers that create rules are written to a "Setup conversation" page that the rules cite, so every rule stays verifiable.
- 2026-11-07 — Same-type questions are grouped (e.g. one "block or review?" for all approval tiers) to keep big-company setup short.
- 2026-11-07 — Prohibitions with "except/unless" can be set to review instead of block; categories are read only from the rule clause, not its exception.
- 2026-11-07 — Added airfare and ground_transport categories so flight and taxi rules don't collide with general travel budget lines.
- 2026-11-07 — Full working app served by the API at /app (overview, grants with coverage, policy chat, rulebook, expenses with live budget and history) so the whole flow can be demoed without the Next.js app or a key; the Next.js UI is still where the polished version will live.
- 2026-11-07 — Allowed expenses spend the grant budget line matching their category; app state (rulebooks, log, budget) is in memory with POST /api/reset for a fresh demo.
- 2026-11-07 — QA pass: approvals from the Rulebook respect unanswered chat questions and stay in sync with the chat; damaged/scanned PDFs return clear 400s; approver roles match case- and spacing-insensitively; flights, hotels and taxis count against the travel budget line; grant budget is only spent when a grant ruleset is checked; unknown expense categories are rejected (422); the chat skips a "vague" cap question when that category already has a cap, and recognises duplicate typed rules.
- 2026-11-07 — Grant budgets come from the agreement's budget table (compiler/budget.py), each line cited like a rule; lines a rule refers to but the agreement doesn't price are listed as missing and can be entered by hand. Budgets are per grant (two grants can both have a travel line); spend is recorded only when the expense was checked against exactly one grant. The hard-coded demo budget is gone from the app.
- 2026-11-07 — Rules narrower than our categories ("spousal travel", "Uber Black", "laptops", "purchases from Amazon", "conference fees") are held back instead of applied to the whole category; the chat explains and offers review-all / block-all / skip. The check runs in code on every proposed policy rule, from Claude or the offline reader (compiler/narrow.py).
- 2026-11-08 — Setup chat wording: questions name the situation ("What should happen when a meal costs more than $75?") and choices say what happens ("Don't allow it" / "Allow it, but flag it for someone to check"); no bare "Block it". Rule descriptions use "not allowed" / "flagged for review". Each question shows "(n of N)", each answer gets a concrete engine-generated example, the final step recaps every rule, and "Undo last answer" steps back one answer (approving in the Rulebook clears undo history).
- 2026-11-08 — New clause splitter (compiler/sentences.py): PDF line wraps no longer split sentences; abbreviations ("No.", "e.g.", "rev.") and heading numbers ("Article 2.", "1.") don't end sentences; newlines break only before headings/numbered clauses, after a short heading line, at budget-table rows, or between short typed list items. Headings are marked and left out of coverage and the offline reader. Used everywhere sentences are split.
- 2026-11-08: A higher approver in a policy's threshold ladder (manager < director < CFO, from its company-wide approval_required rules) covers lower tiers. Category approvals (IT for software) and other rulesets (a grant's program officer) stay separate. Why: real spend-authority chains work this way; a CFO-signed $60k purchase was being blocked for lacking manager sign-off.
- 2026-11-09: Setup questions suggest an answer from the policy's own wording (the rule's sentence first, then consequence sentences elsewhere like "Violations ... denial of reimbursement", then firm-vs-soft wording) and cite it; the person still picks. Typed replies ("allow it", "you pick") answer the open question. Choices now read "Reject it" / "Send it to someone to decide". Why: "Allow it, but flag it" read as approving overspend, and typed answers were treated as new rules.
- 2026-11-09: Setup questions are asked per rule with choices in that rule's terms (item, amount, approver, exception) and name who reviews (the rule's approver, else the policy's lowest company-wide approver, else finance team); a 'Same for all N' shortcut keeps long policies fast. Progress total stays fixed and auto-skipped questions count as done. Why: generic 'send it to someone to decide' choices didn't say what happens or who decides.
- 2026-11-09: Cap and approval questions offer Reject or Approve anyway (new action 'allow': the engine passes it with a note in the trace); no 'send to manager' (nothing routes it yet) and no 'Same for all' shortcut. Rules with an exception still offer Hold for review vs Reject, since whether the exception applies is unknown and ambiguity must escalate.
- 2026-11-09: The full app moves into /web (Next.js, at /app) with C's area agreed by Mihika; it calls the API through a same-origin /api rewrite (FINEPRINT_API_URL), and rule descriptions come from the API (RuleCard.description) so wording lives in one place. api/static/app.html stays as a fallback until the Next app is accepted.
- 2026-11-09: Redesigned /web to avoid template looks: ruled sections instead of rounded cards, colored marks instead of pills, ledger tables, a transcript-style policy chat with lettered choices, IBM Plex instead of Geist, 3px radii. The landing hero shows a real clause and a real decision from the demo instead of an illustrative dashboard; the old Live Studio section is off the page (files kept).
- 2026-11-09: Visual identity is a press proof: Archivo (expanded for display) + Martian Mono, process-ink palette (black, magenta accent, highlighter yellow on quoted clauses), crop marks and a paste-up grid. The home page shows only real demo output, generated by scripts/export_home_demo.py into web/src/lib/home-demo.ts.
- 2026-11-09: Palette switched from magenta/yellow to Ocean Breeze: Deep Twilight ink and panels, Bright Teal Blue accent (Turquoise Surf in dark mode), Frosted Blue highlighter, Light Cyan paper tint. Verdict colors unchanged.
